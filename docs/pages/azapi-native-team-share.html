backgroundwhy this exists

Azure teams are stuck between two imperfect choices.

AzureRM

Typed, but expensive to ship

  • Schema design is hand work
  • Expand / flatten code is mechanical and repetitive
  • SDK or Pandora churn can block delivery even when the ARM API still works
  • HashiCorp coordination and PR review are slow
  • Final calls usually sit with HashiCorp
azapi_resource

Flexible, but shifts risk to users

  • Not exercised like a curated typed resource
  • API behavior is a black box to Terraform planning
  • Lifecycle, defaults, and drift responsibility move to users

We want AzureRM-like authoring — while keeping azapi_resource for the long tail.

scenarioswhere dynamic hits the wall
Why native matters

azapi_resource has hard structural limits.

Wall 01

Plan-time replacement

Generic dynamic bodies cannot express conditional, per-attribute RequiresReplace.

Wall 02

Multi-API resources

One azapi_resource maps to one ARM API call. Real Azure resources often do not.

Wall 03

First-class state logic

Computed outputs, defaults, cross-field rules, and ARM workarounds need a typed resource boundary.

scenario 01replace vs update

Native can tell Terraform what must be replaced before apply.

azapi_resource

Generic PUT, then ARM decides

The dynamic body changes. If the property is immutable or conditionally immutable, users often discover it when ARM rejects the update during apply.

AzAPI native

Per-attribute plan modifier

azwise knowledge bakes replacement rules into the schema. Terraform plan can show exactly which attribute forces replacement.

exampleswhat native can encode that generic dynamic cannot

AzAPI Native gives us a place to encode real Azure behavior.

Role Definition

Wait for update convergence

AfterUpdate uses the PUT response updatedOn, waits for createdOn to revert, and requires 12 consecutive settled reads so post-apply refresh does not see stale permissions.

Key Vault

purge_on_destroy

A synthetic behavior-only attribute drives an AfterDelete purge call against deletedVaults/{name}, freeing the vault name after soft-delete when purge protection allows it.

Web Site

Strip ARM default rules

ARM echoes implicit ipSecurityRestrictions default rules with priority 2147483647. Native reads the config API, strips the sentinel rule, and prevents drift.

These are not schema trivia. They are operational behaviors that belong in a typed per-resource boundary.

developer experiencenative vs hand-written AzureRM work

AzAPI Native shifts work from provider plumbing to behavior.

No schema design

1:1 API mapping

The generator turns Azure's schema into Terraform attributes; we customize only where API behavior demands it.

No flatten / expand

Generic wrapper

The shared mapper handles ARM JSON ↔ typed state dynamically, without per-resource conversion code.

No CRUD methods

Shared lifecycle

The Base owns create, read, update, delete, import, timeouts, mapping, and hook execution.

Source of truth

Name, ARM type, API version, schema, parent scope, writable scopes, and baked timeouts.

Base resource

Shared lifecycle

CRUD, mapping, import, default handling, and hook dispatch are generic.

Hooks + data source

Targeted behavior

Hooks encode API quirks; data sources are generated automatically from the same schema.
